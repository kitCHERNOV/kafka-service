Это быстрый сервис на Go, который работает как надёжный посредник для Apache Kafka. Я его спроектировал так, чтобы он выдерживал большие нагрузки, отвечал мгновенно и не падал.

Главная фишка — это «прогретый» кэш. Как только приложение запускается, оно сразу подгружает все самые важные данные прямо в оперативную память. Это решает проблему «холодного старта», когда приложение после запуска сначала тормозит. Здесь же — максимальная скорость с первой секунды.

Вот как это работает:

Прогрев кэша: Перед тем как начать работать, сервис уже держит все нужные данные под рукой в быстрой памяти. Никаких задержек на «раскачку».

Всё асинхронно: Благодаря Kafka, сервис не ждёт, пока одна задача выполнится, а сразу берётся за следующую. Это помогает ему легко справляться с кучей запросов и делает его более живучим.

Обновления в реальном времени: Я использовал подход через выделение отдельного канала Kafka для результатов, чтобы сервер сам отправлял обновления в браузер. Это очень легковесный способ, который не грузит систему и позволяет пользователю видеть изменения мгновенно.

Легко масштабируется: Если одного сервера станет мало, можно просто запустить ещё несколько копий приложения. Kafka поможет распределить между ними нагрузку.


# Запуск Брокера и Базы Данных
```
docker-compose up -d
```

# Запуск серверной части приложения
```
go run backend/cmd/service/service.go
```

# Запуск клиентской части приложения
```
go run frontend/main.go
```
